# grafana-plugins

Monorepo of Grafana plugins (panels). Each plugin lives in `packages/` and is
versioned/signed independently. There are no datasource plugins — the panels consume
existing datasources (a Prometheus-compatible metrics source and a trace source such as Tempo).

## Layout

```
grafana-plugins/
├── AGENTS.md          # canonical guide (architecture, build, conventions) — read first
├── specs/             # spec-driven: requirements / design / tasks per feature
│   └── monorepo-foundation/   # structural decision (monorepo) + rationale
├── packages/          # one directory per plugin (empty until the first plugin is created)
├── pnpm-workspace.yaml
└── package.json       # recursive scripts (build/test/lint via workspace)
```

## Quick start

No local SDKs — everything runs through Docker (Node 22 + pnpm). See `AGENTS.md` for
the full commands and the flow to create a new plugin.

### Run Grafana locally (with the plugin loaded)

```bash
cd packages/staffops-servicemap-panel

# 1. Create .env from the example (fill in your METRICS_URL and TEMPO_URL)
cp .env.example .env

# 2. Build the plugin (produces dist/)
docker run --rm -v "$(pwd)/../..:/w" -w /w/packages/staffops-servicemap-panel node:22 npm run build

# 3. Start Grafana (13.x, network_mode=host, plugin unsigned allowed)
docker compose up -d

# Grafana at http://localhost:3000 (anonymous admin, no login required)
# The provisioned dashboard is at: Dashboards → browse
```

Each plugin ships its own `docker-compose.yaml` + `provisioning/` + `.env.example`.
The compose extends `.config/docker-compose-base.yaml` (generated by `@grafana/create-plugin`),
mounts `dist/` as the plugin volume, and provisions datasources from `.env` variables.
