# AGENTS.md — grafana-plugins

Canonical guide for humans and AI tools working in this repo. Tool-specific files
(`CLAUDE.md`, `.cursorrules`, …) are 1-line pointers to this file — never duplicate
content.

## What this repo is

A monorepo of **Grafana panel plugins**. Each plugin is a self-contained package in
`packages/`, versioned and signed independently. There are **no datasource plugins**
and **no Go backend** — every plugin is frontend-only (React + TypeScript) and
consumes datasources that already exist (a Prometheus-compatible metrics source with Tempo
service graph metrics, and a trace source such as Tempo)
via the `DataFrame`s Grafana passes to the panel.

## Layout

```
grafana-plugins/
├── AGENTS.md                 # this file (canonical)
├── CLAUDE.md                 # pointer → AGENTS.md
├── specs/                    # spec-driven docs (requirements/design/tasks) per feature
│   └── <feature>/
├── packages/                 # one directory per plugin (+ shared libs when they earn their existence)
│   └── <plugin>/
├── pnpm-workspace.yaml        # workspace = packages/*
└── package.json              # recursive scripts (build/test/lint)
```

`packages/` starts empty. A shared library (e.g. `packages/graph-core`) is created
**only when a second consumer actually needs it** — no speculative abstraction (rule
of three).

## Prerequisites — no local SDKs

The dev machine has **no Node/pnpm installed**. Everything runs through Docker with
`node:22` (Grafana plugin tooling requires Node ≥22). pnpm is provided via corepack inside the container.

```bash
# Base pattern
docker run --rm -v "$(pwd):/w" -w /w node:22 sh -c "corepack enable && <command>"
```

## Common commands

```bash
# Install all workspace deps (pnpm)
docker run --rm -v "$(pwd):/w" -w /w node:22 sh -c "npm i -g pnpm@latest >/dev/null && pnpm install"

# Build / test a plugin — run the package scripts directly (see "pnpm build gate" below)
docker run --rm -v "$(pwd):/w" -w /w/packages/<plugin> node:22 npm run build
docker run --rm -v "$(pwd):/w" -w /w/packages/<plugin> node:22 npm run test:ci
```

> **pnpm build gate (known):** pnpm 10+ blocks dependency build scripts (`@swc/core`,
> `@parcel/watcher`) and its `pnpm run`/`--filter` pre-run check then exits non-zero
> (`ERR_PNPM_IGNORED_BUILDS`). Those deps ship prebuilt binaries and don't need their
> postinstall, so builds succeed when invoked with `npm run` inside the package dir
> (bypassing pnpm's runner). Hardening the pnpm allowlist config so `pnpm -r build`
> works cleanly is a tracked follow-up.

For interactive dev + live Grafana, each plugin generated by `@grafana/create-plugin`
ships its own `docker-compose.yaml` that mounts the built plugin into a Grafana
container. Unsigned plugins are blocked by default; the generated compose sets
`GF_PLUGINS_ALLOW_LOADING_UNSIGNED_PLUGINS=<plugin-id>` for local dev.

## Adding a new plugin

> Spec first. Do not scaffold or code a plugin before its `specs/<plugin>/` is written
> and reviewed.

1. Write `specs/<plugin>/{requirements,design,tasks}.md`.
2. Scaffold the panel via `@grafana/create-plugin` non-interactively (verified flags) into
   `packages/`:
   ```bash
   docker run --rm -v "$(pwd):/w" -w /w/packages node:22 \
     sh -c "npx -y @grafana/create-plugin@latest --plugin-type=panel --plugin-name=<name> --org-name=staffops --no-backend"
   # Docker writes as root — restore ownership:
   docker run --rm -v "$(pwd):/w" -w /w node:22 chown -R $(id -u):$(id -g) packages/
   ```
   This creates `packages/staffops-<name>-panel` (folder = plugin id). It ships its own
   `.config/` (webpack/jest/eslint), `docker-compose.yaml`, provisioning, and CI. Reconcile
   the generated `LICENSE`/`license` to MIT and drop the `packageManager` pin (we use pnpm).
3. Wire it into the workspace (it is picked up by `packages/*` automatically).
4. Implement against the spec; keep coverage ≥90%.

Note: `@grafana/create-plugin` manages a per-plugin `.config/` directory (webpack,
jest, eslint, prettier) that it updates via its own `update` command. Do not fight
that model with a competing root config.

## Conventions

- **All documentation is English** — in-code (comments, identifiers, commit messages)
  and standalone docs/specs alike. This repo's documentation language is English.
- **Tests ship with the code**, ≥90% line coverage, measured in CI. Author of the
  code is not the sole author of its tests (independent verification).
- **Conventional Commits**; never commit or push without explicit approval.
- **Spec-driven**: `specs/` at the repo root (neutral, versioned). No `.kiro/specs`.
- **Versioning is per-plugin** (each `plugin.json`), milestone-based — not one version
  for the whole monorepo.

## Cross-tool parity

Every artifact must behave identically under Kiro CLI and Claude Code. This is a
product repo (the plugins are neutral), and the agent guidance lives only here in
`AGENTS.md`; tool-specific files are pointers.

## Gotchas

- Unsigned plugin → Grafana refuses to load unless allow-listed (dev compose handles it).
- `create-plugin` output is opinionated (its own `.config/`); respect it.
- Node graph data contract: reuse Grafana's native nodes/edges frame convention so the
  plugin stays compatible with Tempo service graph and similar sources.
